CHAPTER 3 · 평가기관 협업
IP 가치평가기관 협업 프로세스

LLM 평가 엔진, 지정 평가기관, 플랫폼 운영사, 은행이 평가 단계에서 주고받는 일의 순서와 책임, 평가사의 화면 업무 절차, 소통·이견 조정 체계를 정한다.

3.1협업 원칙

① 자동 보고서는 초안LLM 평가 엔진이 만든 보고서와 자동 산출 가치는 평가사 검토 전의 사전평가 자료다. 블록체인에 기록되고 LTV 판정에 쓰이는 값은 평가사가 확정한 적용 가치다.
② 평가의 독립성평가사는 신청금액이나 LTV 통과 여부에 맞춰 가치를 조정하지 않는다. 적용 가치는 보고서 근거와 평가사의 전문 판단으로 정한다.
③ 근거의 기록자동 산출 가치와 다른 값을 적용하면 그 이유를 검토 사유에 남긴다. 검토 사유는 확정 내용에 포함되어 그 해시가 블록체인에 기록되므로 나중에 대조할 수 있다.
④ 역할의 분리평가기관은 담보가치를, 은행은 여신 여부를 판단한다. 같은 신청에서 평가사와 은행 담당자는 같은 지갑이 될 수 없다.
⑤ 번호 기준 소통기관 간 확인은 신청번호(LN-…)와 평가 작업번호를 기준으로 하고, 상태는 블록체인 기록을 기준으로 판단한다.

3.4평가 진행 상태별 조치

화면 상태의미담당조치
접수 대기신청 저장, 평가 서비스 접수 전평가사잠시 기다린다. 계속되면 보관 파일로 평가 재시도
접수 확인 중평가 서비스에 자료 전달 중—기다린다.
생성 대기접수 완료, 대기열 순서 대기—기다린다. 화면은 10초 간격으로 자동 갱신된다.
생성 중보고서 생성 중—기다린다(통상 10분 내외). 장시간 지속되면 4.4절 B5
기업 확인 필요사업자번호 자동 확인 실패평가사사업자번호 확인에 신청서와 같은 10자리 번호 입력(4.4절 B4)
검토 대기보고서 도착평가사검토 후 확정(3.5절)
생성 실패보고서 생성 중단평가사 → 운영사사유 확인 후 재시도. 반복되면 운영사 보고(4.4절 B1)
미접수평가 서비스가 접수를 거부(대기열 초과 등)평가사안내된 대기 시간 후 재시도(4.4절 B2)
접수 확인 필요접수 여부 불명. 중복 방지를 위해 자동 재접수 차단운영사 → 평가사운영사가 작업번호를 확인하고 평가사가 공급자 작업번호로 접수 복구(4.4절 B3)
평가 확정온체인 확정 완료—'확정 완료 포함'을 체크하면 목록에 표시된다.

3.5평가사 업무 절차

보고서함 확인

메뉴 — IP 가치평가 접수·평가 목록과 상태 배지 작업번호와 최근 확인 시각 보고서·근거자료 내려받기, 특허 원본 확인 평가보고서 미리보기 확정 완료 포함 · 상태 새로고침
  1. MetaMask에서 본인(평가사) 지갑을 선택하고 웹 화면 역할을 IP 가치평가자 · 지정 평가기관으로 선택한 뒤 IP 가치평가 메뉴를 연다.
  2. 접수·평가 목록에서 상태가 검토 대기인 건을 고른다. 화면 위 문구에 검토를 기다리는 보고서 건수가 표시된다.
  3. 담당 여부를 확인한다. 화면 아래 SBT 카드의 '현재 소유 지갑'이 본인 지갑이면 담당 건이다. 목록에는 모든 평가 건이 보이지만, 검토·확정과 원본 열람은 담당 평가사만 할 수 있다.

보고서와 근거자료 검토

버튼내용
PDF 다운로드 · HTML 다운로드평가보고서 본문. 화면 가운데에서 미리 볼 수 있고 '새 창에서 열기'도 된다.
근거·검증 자료근거 확보 상태, 적용 가정, 검증 항목(quality)
근거 추적 자료보고서 문장별 근거 추적(trace)
소요시간 · 진행 로그단계별 생성 시간(timing)과 진행 기록(log). 오류 문의에 쓴다.
특허 원본 확인 (지갑 서명)차주가 제출한 공고전문 원본. 평가 중(SBT 보유) 단계의 담당 평가사만 MetaMask 서명 후 내려받을 수 있다.

검토 확인 항목

보고서의 평가 대상 특허(등록번호·명칭)가 신청 정보와 같은가
권리범위(청구항)와 잔존 존속기간 분석이 공고전문 원본과 맞는가
시장 규모·매출 전망 등 주요 가정의 근거가 근거·검증 자료에서 확인되는가
자동 산출 가치가 사전평가 값인지, 0 이하인지, 제공되지 않았는지
보고서의 신용등급·재무 요약이 같은 기업(사업자번호)의 자료인가

적용 가치 입력과 온체인 확정

  1. 평가사 적용 가치 (원)에 확정할 금액을 원 단위 정수로 입력한다. 자동 산출 가치가 양수이면 그 값이 미리 채워져 있다.
  2. 보고서 검토 결과·가치 적용 사유를 1~2,000자로 입력한다(3.6절 기준).
  3. 평가사 검토·온체인 확정을 누른다.
  4. MetaMask 서명 창에서 작업(review), 신청번호, 주소를 확인하고 서명한다. 서버가 확정 내용을 암호화해 저장한다.
  5. MetaMask 거래 창에서 평가 확정 거래를 승인한다. 이 거래로 평가가 기록되고 SBT가 소각되며 LTV 판정이 실행된다.
  6. 결과 알림을 확인한다. 평가 확정·LTV 통과 · 여신심사 전달 완료 또는 평가 확정 · LTV 기준 초과로 여신심사 전달 차단
확정 후에는 수정할 수 없다 확정한 적용 가치와 검토 사유는 바꿀 수 없다. 서명 후 거래 승인 전에 중단되면 '확정 내용이 저장되었습니다' 안내가 나오며, 이때는 같은 적용 가치와 같은 검토 사유로만 다시 확정할 수 있다. 다른 내용을 넣으면 이미 준비한 평가 확정 내용이 있습니다. 오류가 난다.

3.6적용 가치 결정과 검토 사유 작성 기준

적용 가치 결정 기준

상황처리 기준
자동 산출 가치를 그대로 적용보고서 근거와 가정이 타당하다고 판단한 경우. 검토 사유에 확인한 자료와 범위를 적는다.
자동 산출 가치와 다른 값 적용미확인 가정 제외, 유사 거래 사례 반영 등 조정이 필요한 경우. 조정 근거와 조정 폭을 적는다.
자동 산출 가치가 '사전평가 값'확정 평가액이 아니므로 평가사가 근거를 검토해 결정한다.
자동 산출 가치가 0 이하이거나 제공되지 않음그 값으로는 LTV 판정을 통과할 수 없다. 평가사가 근거를 갖춘 가치를 산정하고 사유를 적는다. 근거가 부족하면 보수적으로 산정하며, 그 결과 자동 거절될 수 있다.
보고서 근거가 명백히 부족하거나 대상 특허가 다름확정하지 않는다. 작업번호와 함께 운영사에 보고한다.

참고: 계약은 신청금액 ≤ 적용 가치 × 70%일 때 통과시킨다. 평가사는 이 기준을 알고 있어야 하지만, 3.1절 독립성 원칙에 따라 통과 여부에 맞춰 가치를 정하지 않는다.

검토 사유 작성 기준

구성 요소작성 내용
① 검토 범위확인한 자료(보고서, 근거·검증 자료, 공고전문 원본 등)
② 핵심 판단기술성·권리성·시장성 가운데 가치에 영향을 준 사항
③ 가치 조정자동 산출 가치 대비 조정 여부, 조정 폭, 근거
④ 결론적용 가치
작성 예시 (가상) 보고서의 기술성·권리성 분석과 독립항 2개·종속항 9개의 권리범위를 확인함. 시장성 항목의 매출 전망 중 근거자료가 확인되지 않은 2027년 이후 추정치는 반영하지 않고, 자동 산출 가치 1억 1,800만원에서 약 7%를 하향해 적용 가치 1억 1,000만원으로 확정함.
  • 개인정보(대표자 연락처·주소 등), 차주 영업비밀 원문, 확인되지 않은 사실의 단정은 적지 않는다.
  • 검토 사유는 암호화되어 저장되지만, 배정된 은행 여신담당자가 심사 화면에서 그대로 읽는다.

이견 조정 절차

은행이 확정된 평가 결과에 이견이 있을 때 다음 순서로 처리한다.

  1. 여신담당자가 이견 내용(신청번호, 쟁점, 근거)을 운영사를 거쳐 평가기관에 전달한다.
  2. 평가기관이 검토 의견을 회신한다.
  3. 시스템에서는 확정된 평가를 다시 열 수 없다. 재평가가 필요하다고 합의하면 은행이 해당 건을 최종 거절하고, 차주가 새로 신청한다. 새 신청은 새 평가 작업으로 진행된다.
  4. 이견과 회신 내용은 각 기관이 신청번호 기준으로 보관한다.

담당 평가사를 바꿔야 하는 경우

배정은 신청별로 고정되어 화면에서 바꿀 수 없다. 이해상충이나 장기 부재로 담당 평가사가 처리할 수 없으면 다음과 같이 한다.

  1. 평가기관이 운영사에 즉시 알린다.
  2. 해당 건은 진행하지 않고, 차주에게 새 신청을 안내한다. 운영사는 필요하면 배정 대상 평가사를 서버 배정 설정으로 지정한다.
  3. 장기 부재가 예정되면 미리 운영사에 알려 신규 배정 대상에서 빼고, 진행 중인 건은 부재 전에 처리한다.
권한 회수의 영향 지갑 권한을 회수하면 그 지갑이 담당인 진행 중 신청은 더 이상 처리할 수 없다. 단순 배정 제외가 목적이면 권한 회수 대신 배정 설정을 조정하고, 권한 회수는 진행 건을 마친 뒤 실행한다.

3.8평가 품질 관리

  • 근거 충분성 확인 — 보고서 생성이 끝났다고 근거가 충분하다는 뜻은 아니다. 보고서에는 확인되지 않은 매출·적용률 등의 가정이 들어 있을 수 있으므로 평가사는 근거·검증 자료를 반드시 확인한다.
  • 표본 점검 협의안 — 평가기관은 매월 확정 건 중 표본을 골라 보고서·검토 사유·적용 가치의 적정성을 점검하고 결과를 운영사·은행과 공유한다.
  • 사후 추적 협의안 — 승인 건의 상환 결과와 적용 가치를 비교해 평가 기준 개선에 활용한다.
  • 오류 피드백 — 대상 특허 불일치, 명백한 수치 오류 같은 보고서 오류는 작업번호와 함께 운영사에 전달해 평가 엔진 개선에 반영한다.

3.9정보보호 의무

  • 원본 특허 PDF는 평가 중(SBT 보유) 단계에서만 열람할 수 있다. 확정으로 SBT가 소각되어도 이미 내려받은 사본은 시스템이 회수할 수 없으므로, 평가기관이 검토 종료 후 파기한다.
  • 보고서의 기업 재무·신용 정보는 신용정보에 준해 관리하고 업무 목적 외로 이용하거나 제공하지 않는다.
  • 적용 가치는 블록체인에 공개 기록된다. 검토 사유·신용등급·재무 점검 결과는 암호화해 저장하고 해시만 블록체인에 기록한다.
  • 평가사 지갑의 개인키는 평가사 본인만 관리한다. 분실·유출이 의심되면 즉시 4.4절 D1 절차를 따른다.
